# 新桥接入指南（小白版）

本文教你：当你要**换一座新的大桥**、手里有一份**新的成品报告 docx**、数据放在**新的目录**时，怎么一步步接入并生成报告。

全程只需要几条命令，照着复制粘贴即可。

---

## 0. 先准备好 4 样东西

| 东西 | 说明 | 有没有现成的 |
|---|---|---|
| 成品报告 | 新桥的分析报告 `.docx`（人工写好的那一版） | 你提供 |
| 统计值 | `统计值/<传感器编号>.json` 等 | 需要预处理产出，或从该桥已有环境复制 |
| 图库 | `图库/<传感器编号>/<特征>/*.png` | 需要预处理产出，或从该桥已有环境复制 |
| 传感器名称对照 | `传感器对照/传感器名称对照/<新桥>.json`（固定产物） | 需要从《五座桥测点编号表格.docx》生成，或已有 |

> 如果新桥的“统计值/图库/名称对照”还没有，先跑数据处理管道：
> `python preprocess/pipeline.py --raw <秒级数据目录> --daily <日级数据目录> --charts <图库目录> --stats <统计值目录> --sensor-map-docx <测点编号表格.docx> --bridge <桥名>`

---

## 1. 把文件放进项目目录

推荐结构（在项目根目录下）：

```
项目根目录/
├── inputs/                        ← 新建，放成品报告
│   └── 新桥大桥.docx
├── templates/                     ← 生成的模板放这里
├── preprocess/统计值_<期>/<桥名>/  ← 新桥统计值（含 季度总结/季度统计.json）
├── preprocess/图库_<期>/<桥名>/    ← 新桥图库
├── preprocess/传感器对照/          ← 固定产物（传感器编号名称.json、
│                                    传感器名称对照/<新桥>.json）
└── outputs/                       ← 生成的报告输出到这里
```

直接把新桥的成品报告拷到 `inputs/`，统计值/图库拷到 `preprocess/` 下
对应期次（如 `统计值_2026.1~3/<桥名>/`、`图库_2026.1~3/<桥名>/`）目录即可。

---

## 2. 识别成品报告，自动生成模板（一条命令）

```bat
python analyze_report.py --input "inputs\新桥大桥.docx" --annotate "outputs\template_新桥大桥_v1.docx"
```

这条命令会：

- 扫描成品报告，判断哪些数字、表格、图表是“动态的”（要更新）；
- 生成标注模板 `outputs\template_新桥大桥_v1.docx`（里面是 `{{stats.*}}`、`{{cell.*}}`、`{{chart.*}}` 占位符）；
- 生成识别结果 `outputs\analysis_新桥大桥.json`。

跑完把模板移到 `templates\`：

```bat
move "outputs\template_新桥大桥_v1.docx" "templates\"
```

## 3. 创建新桥配置文件（复制赤石的配置来改）

复制 `config/config_chishi.json` 为 `config/config_新桥大桥.json`，只改下面几处：

```json
{
  "template": "templates/新桥大桥_template_v1.docx",
  "output_dir": "outputs",
  "source_report": "inputs/新桥大桥.docx",
  "analysis_file": "outputs/analysis_新桥大桥.json",

  "report": {
    "name_prefix": "新桥大桥",
    "with_timestamp": false
  },

  "bridge_data": {
    "enabled": true,
    "bridge_name": "新桥",
    "stats_dir": "preprocess/统计值",
    "charts_dir": "preprocess/图库",
    "sensor_map": "preprocess/传感器对照/传感器编号名称.json",
    "overview": "preprocess/统计值/总览.json",
    "name_dict": "preprocess/传感器对照/传感器名称对照/新桥大桥.json",
    "metrics": {
      "temperature": { "feature": "WSD(temp)", "unit": "℃", "label": "环境温度" },
      "humidity": { "feature": "WSD(rh)", "unit": "%", "label": "环境湿度" },
      "wind_speed": { "feature": "FSFX2(spfs)", "unit": "m/s", "label": "风速" },
      "cable_force": { "feature": "", "unit": "kN", "label": "索力" },
      "displacement": { "feature": "GNSS(Δx)", "unit": "mm", "label": "位移" },
      "deflection": { "feature": "", "unit": "mm", "label": "挠度" },
      "strain": { "feature": "YB(rsg)", "unit": "με", "label": "应变" },
      "vibration": { "feature": "", "unit": "m/s²", "label": "振动" },
      "rotation": { "feature": "EZJD(xJd)", "unit": "°", "label": "转角", "aliases": ["倾角"] },
      "crack": { "feature": "LF(Δx)", "unit": "mm", "label": "裂缝" },
      "structure_temperature": { "feature": "WD(temp)", "unit": "℃", "label": "结构温度" }
    },
    "sensor_exclude": [],
    "sensor_aliases": {},
    "chart_map": {}
  }
}
```

各字段含义：

| 字段 | 含义 |
|---|---|
| `template` | 第 2 步生成的模板路径 |
| `source_report` | 成品报告路径（生成报告时不会打开它，只是用来推导 analysis 文件名；保持和上面一致即可） |
| `analysis_file` | 第 2 步生成的识别结果 |
| `report.name_prefix` | 输出文件名前缀，如 `新桥大桥2026.1~3.docx` |
| `bridge_data.bridge_name` | 桥名，用于匹配名称对照表 |
| `bridge_data.metrics.<指标>.feature` | 该桥各指标对应的特征编码（不同桥可能不同，先按赤石抄，跑完看覆盖度再调） |
| `sensor_exclude` | 数据异常要排除的传感器编号 |

## 4. 生成报告（一条命令）

```bat
python run_agent.py --config config_新桥大桥.json --mode quarterly --date 2026-03-31
```

`--mode` 支持：`quarterly`（季度）/ `yearly`（年度）/ `monthly`（月）/ `weekly`（周）。
`--date` 是报告期结束日，季度模式用它定位是哪个季度。

生成的文件在 `outputs\` 下，名字类似 `新桥大桥2026.1~3.docx`。

如果想用 `--bridge` 而不是 `--config`，把新桥加进 `bridges\registry.json`：

```json
{
  "id": "xin_qiao",
  "name": "新桥大桥",
  "config": "config_新桥大桥.json",
  "host": "",
  "port": 8080,
  "token_env": "BRIDGE_XINQIAO_TOKEN"
}
```

然后：

```bat
python run_agent.py --bridge xin_qiao --mode quarterly --date 2026-03-31
```

## 5. 检查报告质量（3 个必查点）

1. **表格数值**：打开报告，找“监测统计”表，看每一行是不是**不同位置各自的值**。如果全是同一个数或“—”，说明该位置没匹配到传感器——检查 `bridge_data.metrics.<指标>.feature` 和 `统计值/传感器名称对照/<新桥>.json` 是否齐全。
2. **图表数量**：识别器偶尔会漏标图表。看 `outputs\analysis_新桥大桥.json` 里 `chart_texts` 的数量，和成品报告实际图数对比。漏了就在模板里手动加 `{{chart.自定义ID}}`，并在配置 `bridge_data.chart_map` 里指定它对应哪个传感器。
3. **图表顺序/内容**：同一节内时程曲线图应在前、直方图在后；温度节里不应出现湿度图。发现不对，优先检查名称对照表和 `chart_map`。

---

## 6. 以后每次更新（只改日期）

同一座桥、同一份模板，以后每期只需要：

```bat
python run_agent.py --bridge xin_qiao --mode quarterly --date 2026-06-30
```

不用重新识别、不用改配置。

## 7. 常见问题

**Q：`source_report` 指向的文件不存在，能生成吗？**
能。生成报告不读 source_report 原文件，只用来推导 analysis 文件名。它只在第 2 步识别时真正被打开。

**Q：报错 `No module named 'docx'` 或奇怪的 docx 错误？**
服务器上可能装错成旧版 `docx` 库。执行：
```bat
python -m pip uninstall docx -y
python -m pip install python-docx
```
再验证 `python -c "import docx; print(docx.__file__)"`，路径应是 `...\site-packages\docx\__init__.py`。

**Q：表格里全是“—”或同一值？**
位置→传感器没匹配上。检查：① 名称对照表有没有这座桥；② 统计值目录里有没有对应传感器 json；③ 报告期内有没有数据（看 `outputs\last_run.json` 的 `missing_cells`）。

**Q：识别后图表少了很多？**
当前识别器对“xxx_time_series / xxx_histogram”这类行偶尔会漏。处理：手动在模板补占位符，或把漏掉的图注行改成规范写法（如“跨中断面环境温度时程曲线图”）后重新识别。
